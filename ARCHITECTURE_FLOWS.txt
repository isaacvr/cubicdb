=== EVENT SYSTEM PROBLEMS ===

CURRENT EMITTERS (FRAGMENTED):
  1. lib/classes/Emitter.ts           → Generic event emitter
  2. classes/Emitter.ts               → DUPLICATE de arriba
  3. Svelte createEventDispatcher()    → Component events
  4. Socket.IO handlers               → Real-time events
  5. IPC listeners (config, etc)      → System events
  └─ Resultado: 5 patrones diferentes, sin unified bus

EVENT TYPES (WEAK):
  type DataEvent = DownloadEvent | BluetoothEvent | TimerEvent | ExternalEvent | (string & {})
  Problem: string & {} = basically 'any', no type safety

DOMAIN EVENTS (INCOMPLETE):
  ✅ SolveAdded
  ❌ Missing: SessionCreated, SessionUpdated, AlgorithmAdded, AlgorithmUpdated, etc.

=== KEY ENTITIES & FLOWS ===

ENTITY: Solve
  Create: UI → dataService.addSolve() → (none) → stored
  Read:   UI → dataService.getSolves() → repo query
  Update: UI → dataService.updateSolve() → (none) → stored
  Delete: UI → dataService.removeSolves() → (none) → stored
  
  Problem: No domain events emitted, no handlers
  Current Event: SolveAdded exists in AddSolve usecase only

ENTITY: Session
  Create: UI → dataService.addSession() → AddSession usecase → SessionRepo
  Update: UI → dataService.updateSession() → UpdateSession usecase
  Delete: UI → dataService.removeSession() → (none)
  
  Problem: No events for create/update/delete
  State: AddSession has validation but no event emission pattern

ENTITY: Algorithm
  Create: UI → dataService.addAlgorithm() → AlgorithmIPC → stored
  Read:   UI → dataService.getAlgorithms() → AlgorithmIPC → stored
  Update: UI → dataService.updateAlgorithm() → AlgorithmIPC
  Delete: UI → dataService.removeAlgorithm() → AlgorithmIPC
  
  Problem: Completely IPC-driven, no ports/usecases/events

ENTITY: Reconstruction
  Similar to Algorithm: IPC-driven, no architecture

=== DATA FLOW PATTERNS ===

PATTERN 1: IPC-Direct (Current Default)
  Component → dataService.method() → IPC → Storage
  Events:    None or implicit
  Type-safe: No (any types)
  Testable:  No
  Examples:  Algorithms, Reconstructions, Cache, etc.

PATTERN 2: UseCase+Port (Emerging)
  Component → dataService.method() → UseCase → Repository → Storage
  Events:    Some (SolveAdded in AddSolve)
  Type-safe: Partial
  Testable:  Better
  Examples:  Solves, Sessions

PATTERN 3: External Events (Listeners)
  IPC → [listener] → dataService.emit()
  Examples: 
    - Download progress (config.addDownloadProgressListener)
    - Bluetooth (config.addBluetoothListener)
    - External timers (config.addExternalConnector)
  Problem: Event names are strings, handlers are scattered

=== CURRENT PROBLEMS SUMMARY ===

1. FRAGMENTED EVENTS
   5 different event systems, no unified bus
   String-based event names (no type safety)
   Missing ~80% of domain events

2. INCOMPLETE ARCHITECTURE
   Some entities have ports/usecases (Solve, Session)
   Most entities bypass architecture (Algorithm, Reconstruction, etc)
   Stubs in adapters (return Promise.reject())

3. DATA SERVICE CONFUSION
   lib/data-services/data.service.ts (Svelte store pattern)
   stores/data.service.ts (Class pattern, singleton)
   Different interfaces, confusing which to use

4. NO CONSISTENT INJECTION
   UseCase callbacks optional and manual
   DataService is singleton, not testable
   Components directly call dataService

5. NO EVENT HANDLERS PATTERN
   Events emitted but no unified subscriber system
   Handlers scattered across components/services
   Difficult to trace event flow

=== IPC INTEGRATION POINTS ===

CONFIG (system settings):
  addDownloadProgressListener → listen for download-progress
  addDownloadDoneListener     → listen for update-downloaded
  addBluetoothListener        → listen for bluetooth events
  addExternalConnector        → listen for external timers

STORAGE (IndexedDB / Electron):
  getAlgorithms()
  getAlgorithm()
  addAlgorithm()
  updateAlgorithm()
  removeAlgorithm()
  [same for Reconstruction, Tutorial, Session, etc]

Problem: No abstraction, direct IPC calls mixed in dataService

=== COMPONENT PATTERNS ===

Pattern A (Most components):
  import { dataService } from "@stores/data.service"
  onMount(() => {
    data = await dataService.getAlgorithms()
  })
  on save: await dataService.addAlgorithm(alg)

Pattern B (Some components - Svelte events):
  const dispatch = createEventDispatcher()
  on:click → dispatch("click")
  Parent listens with on:click handler

Pattern C (None yet - would be event-driven):
  import { eventBus } from "@lib/events"
  on save: await eventBus.dispatch(new SaveAlgorithmRequested(alg))
  onMount: eventBus.subscribe(AlgorithmSaved, handler)
